大家好，我是Zack。

我的笔记软件里，关于 AI 的笔记攒了小几百条。

每次刷到一篇好文档，我就收藏、通读、摘抄、写成卡片，标注「已读」。

然后就没了。

真要用的时候，比如要写一段提示词让 agent 干活，我翻遍笔记，找不到一条能直接抄的。

有一阵我怀疑自己学得太少，于是狂补。看文档、看课程、看源码，每天两三个小时。

三个月后我写提示词的水平，和之前一模一样。

后来我把这件事想明白了：**不是学得不够多，是学的过程里从来没有「用」这一步。**

读文档是顺手的事，因为它不用面对阻力。收藏也是顺手的事，因为它不用付代价。

只有真的用出去，才会撞墙。撞了墙，才知道这个知识到底长什么样。

## 我原来的做法

我以前的学习流程是这样的：

搜到一篇好文章 → 通读 → 摘抄要点 → 记一条笔记 → 放进文件夹。

这个流程有一个致命问题：**它没有终点。**

记完之后没有任何东西逼着我拿它做点什么。所以笔记越积越多，我从来没有一次真的「调用」过它们。

我给自己找过一个很体面的理由：这些是「基础」，以后会用到。

这句话我说了大概一年。

后来我粗算了一下：这些笔记里，被我在真实工作里用过的，不到 1%。

剩下 99% 是噪音——它们躺在那里，还会干扰我的判断。

## 换成 4 个动作

现在我的流程只有四步。核心区别是：**每一步都有必须交付的东西，交付不出来就是没学。**

### 动作一：让 AI 出题，不要让它总结

这是我改掉的第一件事。

以前我让 AI「帮我总结一下这篇文章」，它会给我一份结构清晰、读起来很爽的提纲。

那份提纲读完，人是爽了，什么也没留下。

因为总结是**阅读**，而阅读不需要理解。

现在我改成这么问：

```
你是我的面试官，我要学的是【把长任务拆成可验收的步骤】。

不要给我总结，不要给我教程，不要给我要点列表。

直接出 5 道题，每道题都要是我工作中真实会遇到的场景，
题目里必须给出具体的输入：一个报错原文、一段代码、一个数字。

我回答之后，你再判我错在哪，指出我漏了什么，最后给我参考答案。
```

差别在哪：出题这个动作，**强制模型去判断什么是关键**。

它要出 5 道好题，就得先想清楚这个知识点到底包含哪几个可以被考的点。

而总结只是在复述输入。

我做过对比：同一个知识，问「总结要点」和问「出 5 道场景题」，前者我看完什么都不记得，后者我当场就知道自己哪里是空的。

### 动作二：一页纸，只留能抄的那部分

知识不用记多，要记到**能直接抄出来用**的程度。

我现在每张卡片只有四栏，没有第五栏：

```
场景：什么时候用
命令：直接能抄的那一行
判据：做完怎么算成了（必须是能打勾的）
坑：第一次踩的是什么
```

举一个我现在真的在用的例子：

```
场景：让 agent 跑任何可能卡住的命令
命令：timeout 60 <原命令>
判据：60 秒没结束就被杀掉，进程不留在后台
坑：忘了加，agent 一直挂着，我不知道它在等什么
```

这张卡片的价值不在「timeout」这五个字母。

价值在最后那行坑——它是我第一次让 agent 跑一个安装命令挂了 8 分钟才发现的。

下次我写任何命令，脑子里会自动冒出这行。这才叫知识的调用。

一张卡写不满一页，就是你还没想清楚。写满了，就是能用。

### 动作三：当天必须用出去

这条是我的硬规定：**学到一个知识点，当天必须用它做一件真事。**

注意是「真事」，不是练习题。

不是「照着文档写个 demo」，也不是「在笔记里写一段总结」。

是**我今天本来就要做的那件事里的一步**。

比如我今天本来要跑一批脚本、或者发一批内容，那我就得把这个新知识用到这批活里。哪怕只用在其中一条上，也行。

这个约束的价值在于：它把「学」和「干活」绑在一起了。

以前我一天里有一段时间专门「学习」，这段时间是真空的——没有外部约束、没有真实反馈、没有摩擦。

现在没有了。学到的知识点当天就要面对真实环境。

我自己的知识筛选走过弯路，代价很具体。

有一轮我要从一批候选里挑值得跟进的对象，池子里 353 个，我不知道该怎么留。

我当时的做法是「凭感觉选」，挑了 10 个。

后面两轮才发现这里面好几个是 spam——主页挂着正经的技术内容，样本挑得极好，一进主页全是引流。

真正管用的方法不是感觉，是一张事先写死的淘汰清单：关键词过滤 → 查重 → 主页复核最近 3 条 → 粉丝门槛。

353 个过完关键词筛剩 169，最后人工留 10 个，**淘汰率 97%**。

而且这套清单不是从某本书上读的，是被那些 spam 号一条一条骗出来的。第一版错得很离谱，第三版才稳定。

它就是「当天用出去」用出来的。

### 动作四：上机跑一遍，撞一次墙

最后一个动作，也是我认为最值钱的一个。

**理论是真空，真空没有摩擦。**

你在脑子里想通了一个方法论，会觉得它特别合理、特别顺。

只有真机上跑，才会撞墙。

撞墙的时候你会发现一堆「我以为我懂了」的地方：

- 我以为我知道这个参数，实际敲上去报错
- 我以为我理解了流程，实际中间有一步没人讲
- 我以为我知道怎么判断成功，实际判据是模糊的

我前面说的那套筛选清单，第一次跑的时候错得一塌糊涂——这就是墙。

只有撞了墙，第四步才有用：**把这个墙记下来，改那一格。**

所以我的卡片里，「场景」「命令」「判据」三栏很少动。

「坑」这一栏，我一年要重写好几次。

一个知识被掌握的程度，是分层的：

- 最浅：听说过这个词
- 再深：能复述它的内容
- 更深：知道在什么场景该用它
- 最深：知道它什么时候会失效

最后这一层，只有撞过墙才拿得到。

## 怎么判断你是不是真学会了

给你一个我自己用的判据，很硬：

**把你学到的东西，变成一条命令，或者一段能直接粘进对话框的提示词。**

写不成，就是你脑子里还是模糊的。

拿「让 agent 先做只读操作」这个知识举例。

只会说的人写出来是这样：

> 你要先只读地检查一下。

我写出来是这样：

```
先只读，不要改任何文件。

执行这两条，把输出贴给我：
git status --porcelain
git diff --stat

等我确认之后再动手。
```

第二段是可以直接粘进对话框的。

区别在哪儿：第一段没有判据，agent 只能猜；第二段每一步都能打勾。

**判定不了的要求都是废话**——这是我前几天那篇文章里写过的一条。

这两件事其实是同一条：**能不能写出来，就是学没学会的判据。**

我现在的习惯是，每写一条给 agent 的指令，就顺手存进一个文件。

不是因为我记性差，是因为**存下来的那一刻，我就已经把它从「我懂了」变成「我交付过了」**。

## 前后对比

| | 以前 | 现在 |
|---|---|---|
| 看完一份文档 | 存进文件夹 | 出一张四栏卡片 |
| 笔记的终点 | 没有终点 | 交付一条能抄的命令 |
| 学到一个新知识点 | 记下来 | 当天用在一个真活里 |
| 判断标准 | 凭感觉 | 事先写成清单 |
| 撞墙之后 | 换个方向继续试 | 把坑写进卡片，迭代那一栏 |

数字我说得保守一点。「能回忆的比例」我没量过，不敢编。

就写最实在的那条：**我笔记里那些 AI 知识，真正在真实工作里被用过的，不到 1%。**

现在这个数字在涨。

## 两条能迁移的原则

**一、学习的完成标准不是「我懂了」，是「我交付了一个东西」。**

交付物可以是一条命令、一张卡片、一个脚本、一段提示词。

没有交付物的学习等于没发生，你只是读了一遍。

**二、AI 时代这条比任何时候都值钱。**

以前学一个东西，门槛在「能不能找到」——书、课程、文档都有限，你搜到就是赚到。

现在 AI 几秒钟给你一份结构完整的总结。

**获取知识的成本已经趋近于零。**

那什么还值钱？

值钱的是**判断**：知道哪 20% 是关键的、哪 80% 是噪音；知道这个方法在什么场景会失效。

判断力只能从撞墙上长出来，读不出来。

所以我那四步压成一句话就是：

> 少读一点，当天用出去，撞一次墙，把墙记下来。

## 局限也说清楚

这套方法有边界，我用之前先说清楚。

第一，它要求你有真实的活干。没有正在做的事情，「当天用出去」这条执行不了，只剩下记卡片。

第二，头几天会很慢。定标准、撞墙、迭代，这三件事没法跳过。我那套筛选清单改了三版才稳定。

第三，它只适合工具型、方法型知识，不适合需要长期熏习的东西——比如写作的语感、设计审美。这些没法「当天交付」，硬套会变成走形式。

所以我不是说别读书、别看课。

我是说**看完之后多做一件事**：把它变成一个今天就要用出去的东西。

那一分钟的动作，决定了半年之后你手里还剩下什么。

## 最后

这套东西一点都不玄学，就是「少记、当天用、撞墙、改那一格」。

我用了两年多，效果就是：我读过的 AI 文档，留在手里的基本都是能直接抄的。

你那边学新东西是怎么收尾的？看完之后有没有真的用过一次？

特别想听听大家卡在哪一步。有的话，欢迎在留言区告诉我。
